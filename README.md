# Agent 精通路线

这是一个帮助前端开发者学习企业级 AI Agent 工程的实训网站。从来没做过 Agent 开发的人，也能跟着 12 章基础篇实战教程，从零搭建一个企业知识库与工单 Agent。这个 Agent 包含权限检索、人工审批、多租户、审计、评测和部署。之后的 6 章高级篇面向资深 Agent 工程师，覆盖 MCP、上下文工程、LLM 评审校准、性能与可靠性、能力模型和面试，以及从原型走向大规模生产的难点研究路径。

## 从这里开始：实战教程（`#/learn`）

- **配套参考项目**：[course/ticket-agent](course/ticket-agent/README.md) 是一个完整、可运行、有测试的项目。它直接用 Node 24+ 原生运行 TypeScript，后端零依赖，默认使用离线模型，不需要 API Key。
- **代码与项目同步**：教程页面上的源码通过 Vite `?raw` 直接导入这个项目，所以页面上的代码与可运行代码始终一致。
- **每章内容**：
  - 概念
  - 分步操作，配有真实文件、命令和实际输出
  - 常见问题排查，按“现象、原因、解决”整理
  - 需要改代码并用测试证明的练习
- **章节**：
  - 准备：环境
  - 第 1–3 章：模型调用、Agent 循环、带权限的检索
  - 第 4–5 章：事件日志与恢复、审批与幂等
  - 第 6–7 章：HTTP 与 SSE、React 工作台
  - 第 8–9 章：评测门禁、安全与可观测性
  - 第 10 章：部署
  - 第 11 章：接入真实企业系统，以及疑难问题手册
- **高级篇**（每章都有真实代码、测试和“面试追问”）：
  - 第 12 章：MCP Server（stdio + OAuth 保护的 HTTP，服务端发起确认）
  - 第 13 章：上下文工程（上下文预算、压缩、子 Agent 取舍）
  - 第 14 章：错误分析与校准过的 LLM 评审
  - 第 15 章：性能、成本与可靠性（提示词缓存、并发工具、降级熔断）
  - 第 16 章：能力模型、系统设计题、故障演练与面试题
  - 第 17 章：生产难点地图（规模化检索、分布式运行、企业权限、可观测性、真实模型漂移、多 Agent 与记忆、未知故障排查、安全合规），每个难点都给出入手实验、一手资料和衡量标准

## 深入专题

下面这些是原有的 7 个阶段专题，用来补充原理和企业场景，按每周 8–10 小时估算约需 5 个月。实际进度以实训验收结果为准，不保证在固定时间内达到生产能力。

## 功能

- **7 个实训阶段**：模型协议、受控循环、React 工作台、授权检索、评估追踪、可靠调度与安全、预生产交付。
- **站内教学**：14 节课程，包含原理、贯穿案例和可展开的自测答案，不要求先跳到外链才能学习。
- **分步实验**：28 个实验步骤，每步给出行动和预期结果，附提交物要求。
- **代码与模板**：7 份起步/核心参考，包含可离线运行的模型替身测试和评估汇总脚本；其余片段注明前置条件与缺失边界，不冒充完整应用。
- **故障训练**：14 个案例，覆盖流式切块、重复写入、撤权缓存、断线恢复、评估失真、租约失效与备份对账。
- **验收与证据**：14 项可测量的阶段验收；记录提交、验证命令、版本、结果与残余问题。勾选只是自评，网站不执行或审核学员项目。
- **任务清单**：保留原路线的基础/拓展任务及已有进度；总进度包含这些任务和新增验收，旧任务不会自动转为实训通过。
- **拓展代码骨架**：保留原 coding agent 与 reducer 片段，明确标注为非生产实现。
- **学习笔记**：每个阶段都有独立的笔记区。
- **精通标准**：查看七阶段交付检查和能力自评，不将勾选等同于生产认证。
- **进度备份**：任务、笔记和实训证据只保存在浏览器的 localStorage 中，可以导出或导入 JSON；不要记录密钥、真实企业正文或个人信息。

## 如何实训

1. 在首页完成环境、身份和合成文档准备，另建本地实训仓库。
2. 每阶段按“站内课程 → 动手实验 → 故障训练 → 验收与证据”完成闭环。
3. 先使用离线固定响应，再通过服务端环境变量接入真实模型；两种模式的结果分开报告。
4. 企业项目依次加入检索、审批、幂等、持久化、租户隔离、评估与调度，最后完成预生产发布、回滚和备份恢复。

网站本身是静态页面，没有模型代理、数据库或判题服务。这些服务的参考实现在 `course/ticket-agent`，学员在本地运行。供应商密钥不能放到前端。训练阈值只是练习门槛，真实上线仍需要业务、安全与运维审查；课程覆盖常见工程问题，不承诺解决所有难题。

## 运行

```sh
npm install
npm run dev          # 开发服务器
npm test             # 网站与工作台的 Vitest 测试 + 参考项目和 MCP 服务的类型检查与 node:test 测试
npm run test:course  # 只运行参考项目的类型检查和测试
npm run test:mcp     # 只运行 MCP 服务的类型检查和测试（先执行 npm ci --prefix course/ticket-agent/mcp）
npm run build        # 类型检查并输出到 dist/
npm run lint
```

参考项目自身的命令见 [course/ticket-agent/README.md](course/ticket-agent/README.md)。构建产物使用相对路径，可以部署到任意静态托管服务或子路径。

## 修改学习内容

- 实战教程：[src/data/tutorial.ts](src/data/tutorial.ts)。
  - 每一步的 `files` 必须是 `course/ticket-agent` 中真实存在的文件，`src/tutorial.test.tsx` 会检查。
  - 修改参考项目后，要重新运行命令，并更新教程中的“实际输出”。
  - 无法在本地验证的输出（真实模型、Docker 等）必须写 `outputNote`。
- 阶段与原任务：[src/data/roadmap.ts](src/data/roadmap.ts)。
- 站内课程、实验、故障和验收：[src/data/training.ts](src/data/training.ts)。
- 对应参考实现与交付模板：[src/data/trainingExamples.ts](src/data/trainingExamples.ts)。
- 原拓展代码：[src/data/snippets.ts](src/data/snippets.ts)。

进度数据以任务的 `id` 为键保存。修改任务时要保留原有 `id`，删除后的 `id` 也不要重复使用，否则用户已保存的进度会对应到错误的任务。

新增的 ID 和存储规则：

- 教程练习使用 `t-` 前缀，章节笔记保存为 `learn:<章节 ID>`。
- 新增验收使用独立的 `lab` 前缀任务 ID，不复用旧任务的含义。
- 阶段笔记继续以阶段 ID 保存。
- 实训证据保存为 `evidence:<阶段 ID>`，和笔记放在同一份 notes 数据中，兼容原备份格式。

## 技术栈

Vite、React 19、TypeScript、Vitest、Testing Library 和 oxlint。项目不依赖路由库或状态管理库：hash 路由和进度存储都通过 `useSyncExternalStore` 实现。
